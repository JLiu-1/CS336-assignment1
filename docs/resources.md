# 实验规模与共享算力

## 配置档位

| 配置 | 模型 | token 预算 | 用途 |
|---|---|---:|---|
| debug.json | 2 层，D=64，H=4，F=192，T=32，词表从 demo 读取 | 5,120 | CPU 流程检查 |
| m4_pilot.json | 4 层，D=256，H=8，F=704，T=256，V=10K | 4,096,000 | M4 短训练 |
| m5_trial.json | 同课程模型；保留 5000 步日程 | 4,096,000 | M5 探索，可选 |
| m5_baseline.json | 同课程模型 | 40,960,000 | M5 基线 |
| m5_no_rope.json | 同基线，只关闭 RoPE | 40,960,000 | 示例候选；可替换选题 |
| original_optional.json | 4 层，D=512，H=16，F=1344，T=256，V=10K | 327,680,000 | 原规模选做 |

训练 token 数 = microbatch size × 梯度累积次数 × context length × 优化器更新步数。它不是原始语料文件中独特 token 的数量；随机窗口可能重复出现。

默认课程模型约 8,333,568 参数，原配置约 22,696,448 参数（未共享 embedding）。参数量按实际矩阵结构计算。配置只给规模，不承诺达到某个 loss 或运行多少分钟。

降低维度减少矩阵计算和激活，降低训练 token 数减少重复更新。原作业的 B200 用时不能直接用于 5090。最终预算档要经过课程平台实际吞吐、验证/保存耗时、显存和并发 I/O 标定。

## 必做规模的降档

M5 的两条正式运行应使用同一预算档：标准档每次 5000 步；紧张时降到 1000 步；更紧张时 500 步。相应调整 schedule_steps，warmup 可约占总步数 2%。按时间比较时记录实际 tokens，按 tokens 比较时必须等量。不要只缩减候选而保留长基线。

M4 的 500 步 pilot 可以按课堂通知降档。固定 batch 过拟合、恢复一致性、代码测试始终保留。正式数据未发放前用 demo 完成软件检查；demo 不替代正式研究。

## 使用约定

- 42 人组成 14 个三人小组；M1–M3 在 CPU 完成。M4/M5 每组同时最多占用一张 GPU。
- 建议配额起点为 M4 每组 2 GPU 小时、M5 每组 6 GPU 小时，合计 112 GPU 小时；正式配额以课程发布为准。这些不是耗时测量值。
- 验收通过后再提交长作业。优先使用短试跑排错；长作业设置运行上限并定期保存。
- 日志/小报告可保存到个人目录，数据使用课程共享只读目录。需要本地缓存时使用分配的缓存空间。
- CPU 预分词不得自行开满进程；M1 全量预处理与 OWT tokenizer 训练不属于必做。
- 训练失败、排队中断或提前停止都记录真实状态。验证结果有限且完整保存后再报告，不伪造耗时或 loss。
- BF16、编译或融合实现应先验证。默认配置 FP32，避免把数值精度问题与核心实现问题混在一起。

## 原作业要求的取舍

保留分词、Transformer、损失、优化器、训练、生成的完整链路。提供类框架、数据读取、日志、checkpoint、测试接线。BPE 增量优化、严格速度门槛、全部 GPT-2 型号资源推导、全范围 batch sweep、四项消融全部重训、OWT 和 B200 leaderboard 均不作为基础必做。M5 鼓励自主优化，不按实验数量或绝对最低 loss 评分。
